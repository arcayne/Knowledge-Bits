## Risk tier

**Orange.** The PR changes recipe/content-contract versions, the writer/provider trust boundary, and the Knowledge Bits→Nuglet delivery contract. It does not change production migrations, approval/checksum behavior, destructive operations, or privileged credentials.

## Acceptance scenarios checked

- Intended path reconstructed: new back-office intake selects `nuglet.lesson.v2`; NotebookLM supplies research; a separate writer creates one lesson and quiz; editorial QA checks it; media creates the visual and one Conversation; review supports V2 while preserving V1; delivery sends an approved package to Nuglet.
- **Can PDF evidence reach the narrative writer? No.** Accepted PDF snapshots are filtered out by `narrativeSourceText`; PDF-only research ends in `narrative_writer_evidence_missing` (`apps/worker/src/runtime.ts:301,1100`; `apps/worker/src/runtime.test.ts:266`, at the reviewed head).
- **Can source text contain instructions that influence the writer? Yes.** Raw public HTML/plain-text prose is embedded in the user prompt. HTML tags/scripts are stripped, but prose instructions are neither isolated nor explicitly marked untrusted (`apps/worker/src/runtime.ts:1107`; `apps/worker/src/providers/narrative-writer.ts:127`).
- **Maximum total writer context? None is enforced.** Each eligible source is truncated to 60,000 characters. The normal 12-source discovery path permits up to 720,000 source characters before recipes/contracts/assignment, and existing notebook inventory is not capped before assembly (`apps/worker/src/providers/notebooklm.ts:399,434`; `apps/worker/src/runtime.ts:1128`).
- **Writer credentials absent?** The writer client is not created; V2 Create throws `narrative_writer_unconfigured`; the executor records a configuration `needs_human` result (`apps/worker/src/runtime.ts:175`; `apps/worker/src/providers/content-creation-router.ts:29`; `apps/worker/src/executor.ts:238`).
- **Can V2 deliver before Nuglet supports it? Yes, Knowledge Bits can queue and attempt it.** There is no compatibility handshake or feature gate. An unsupported downstream 4xx becomes `needs_human`; success otherwise depends on Nuglet (`apps/api/src/services/standard-nuglet-intake.ts:93`; `apps/api/src/services/delivery.ts:133`; `apps/api/src/services/delivery-adapters/http.ts:76`).
- **Was a real review preview deployed? No.** Both Vercel contexts describe the deployments as `Skipped - Not affected`; the PR comment reports two skipped deployments and provides no review preview URL.

## Blocking findings

1. **PDF evidence is dropped.** A source-grounded writer path that accepts PDF snapshots cannot silently omit them or fail PDF-only research.
2. **Untrusted source prose shares the instruction channel.** Schema/citation checks constrain output but do not stop source-originated instructions from steering framing, actions, or quiz content; no prompt-injection failure-path test exists.
3. **Writer context has no aggregate budget.** Prompt size and truncation behavior depend on an unspecified downstream model limit.
4. **V2 compatibility is documentation-only.** New intake selects V2 immediately, but approval/delivery has no Nuglet capability gate.

## Non-blocking findings

- Learner-facing `publicSources` IDs/labels/publishers are not bound to accepted evidence, even though claim citations are checked.
- “Independent” editorial QA can use the same provider/model as the writer; distinctness is convention, not enforced configuration.
- Missing regression coverage includes unconfigured V2 writer routing, total-context overflow, malicious source prose, invented public-source bindings, downstream V2 rejection, and successful compatible-Nuglet delivery.

## Unproven assumptions

- Production has valid writer configuration and ambient provider credentials.
- The selected writer supports the assembled prompt and strict JSON envelope.
- New intake always uses an appropriately bounded dedicated notebook.
- Nuglet's V2 contract exists, is deployed, and matches this schema.
- A real V2 package has completed provider generation, browser review, approval, and delivery.
- The authenticated deployed review UI renders V2 correctly; Vercel skipped both previews.

## Verdict

**Request changes.** Resolve the four blocking findings or explicitly narrow/gate V2 before merge, then rerun review against the new head SHA.

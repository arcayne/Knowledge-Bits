# Code of Conduct

## Our pledge

We want participation in Knowledge Bits to be respectful, constructive, and safe. Contributors must act professionally and consider the effect of their words and actions on others.

## Expected behavior

Examples of behavior that contribute to a positive environment include:

- using welcoming and inclusive language;
- respecting different viewpoints, experience levels, and identities;
- giving and receiving actionable feedback;
- focusing on the work and its evidence rather than on people;
- accepting responsibility, correcting mistakes, and learning from them; and
- protecting secrets, personal data, private links, and security reports.

## Unacceptable behavior

Unacceptable behavior includes harassment, discrimination, threats, intimidation, personal attacks, sexualized language or imagery, doxxing, publishing private information without consent, deliberate disruption, and public disclosure of security vulnerabilities before private reporting. Repeatedly ignoring project scope or maintainer decisions can also be addressed as disruptive behavior.

## Scope

This Code of Conduct applies in repository issues, pull requests, reviews, project channels, events, and other spaces when a person is representing the project. It also applies when behavior would materially affect the safety or participation of the project community.

## Enforcement

Report sensitive conduct concerns privately through the [GitHub Security Advisory private form](https://github.com/arcayne/Knowledge-Bits/security/advisories/new). This is a provisional shared private channel until the owner establishes a dedicated conduct contact. Do not include secrets or public exploit details.

The current escalation owner is **arcayne**, the repository owner. Maintainers will review reports fairly, protect confidentiality as far as practical, and take action proportionate to the behavior. Possible actions include a request to stop, a warning, temporary limits, removal of content, or removal from project spaces. Retaliation against a good-faith report is not acceptable.

The project has not yet assigned a permanent maintainer-ownership and escalation roster. That assignment is an explicit decision required before a public release.
